# EMP·DEPT로 DB Companion 데모

고객 데이터 없이 설치·용어 검색·SQL 검토·평가·배포 버전 전환을 확인하는 공개 샘플입니다.
데이터 기준은 [Oracle SCOTT 샘플](https://github.com/oracle/dotnet-db-samples/blob/master/schemas/scott.sql)입니다.
`SCOTT/tiger`는 옛 샘플의 이름이며, 여기서는 비밀번호를 지정하거나 기존 계정을 변경하지 않습니다.

1. 기존 EMP·DEPT가 있으면 구조와 행 수를 확인하고 재사용합니다. 기존 샘플의 내용이
   다르면 questions.json의 기대 값도 실제 데이터에 맞게 조정합니다.
2. 샘플이 없으면 **DB 관리 > SCOTT 데모 설치**에서 상태 확인 → SQL 미리보기 →
   동의 → EMP·DEPT 설치를 실행합니다. 전용 일반 계정으로 로그인해야 합니다.
   계정이 없으면 ADMIN의 **계정 생성·권한 설정**에서 일반 계정을 먼저 준비합니다.
   설치는 기존 EMP·DEPT나 관리자 스키마에서 중단하며 DROP을 수행하지 않습니다.
   설치 후 행 수·급여 합계를 재조회합니다. `fixture.sql`은 이 화면이 사용하는 공개 원본입니다.
3. 업무 용어사전에서 저장소·Text 인덱스·이력을 준비하고 glossary.json을 가져옵니다.
4. 함수 > 사전 검색 함수에서 생성 SQL을 확인해 DBC_GLOSSARY_API와
   DBC_GLOSSARY_SEARCH를 생성합니다. 직원 수·급여 합계 질문으로 검색을 확인합니다.
5. 온톨로지에서 EMP·DEPT를 가져옵니다. EMP.DEPTNO → DEPT.DEPTNO 관계와
   빈 부서를 포함하는 LEFT JOIN 업무 규칙을 확인합니다.
6. 최초 배포 버전을 만들고 테스트 화면에서 해당 버전을 선택합니다.
   questions.json의 질문·정답 SQL·기대 결과를 평가 질문으로 등록해 비교합니다.

오답 개선 데모에는 `급여와 수당 합계`를 사용합니다. `SUM(SAL+COMM)`은 NULL인
수당 때문에 급여가 누락됩니다. 사전의 `NVL(COMM,0)` 규칙 또는 Feedback을 보완한
뒤 같은 질문으로 생성 SQL과 실행 결과를 비교합니다. 실패를 실제로 확인한 경우만
오답 사례로 기록하며, 정답 SQL을 실행한 결과를 AI 검증으로 표시하지 않습니다.

기준 데이터에서는 직원 14명, 급여 합계 29,025, 수당 포함 31,225입니다.
부서 40은 직원 수·급여 합계가 모두 0입니다. 이 수치는 fixture.sql을 그대로 설치한
경우의 기준이며 기존 샘플의 데이터와 자동으로 같다고 가정하지 않습니다.

유료 AI 호출은 프로필·전송 내용을 확인한 뒤 실행합니다. fixture.sql은 DDL 자동
커밋과 샘플 INSERT를 포함합니다. 별도 데모 스키마에서만 사용하세요.
