# 대화로 생성·수정·운영하는 사용 시나리오

사용자는 대화 안에서 대상을 찾고, 값을 선택하고, 변경안을 확인한 뒤 적용 결과와 이력을 확인한다. 이 문서는 그 흐름을 기준으로 현재 지원과 보완 순서를 정하는 개발·검증 기준이다. 기능별 API가 있다는 사실만으로 전체 대화가 가능하다고 표시하지 않는다.

기준일: 2026-11-27. 초기 점검 기준점: `b79e4f3`. 아래 대화 예시는 목표 동작이며, 이후 구현·검증한 범위를 표와 [실제 검증 기록](profile-creation-conversation-design.md)에서 구분한다. 초기 목록 작성 이후 별도 승인된 교육용 DB에서 생성·질문 시험을 진행했다.

후속 변경: 기본 채팅의 자유 입력은 LLM이 먼저 받고 메뉴 설명·현재 초안·최근 대화와 조회 Tool을 사용하도록 전환했다. 아래의 **대화 명령** 분류는 초기 구현 기준이며, 최신 동작·검증 범위는 [LLM 대화 설계](llm-conversation-design.md)와 [사용 방법](service-tools.md)에서 구분한다. 전체 시나리오가 실제 모델로 완료 검증되었다는 뜻은 아니다.

## 지원 여부를 읽는 방법

- **기존 기능**: 화면·서비스에 실행 경로가 있다. 실제 실행 검증 여부와는 별개다.
- **대화 명령**: 정해진 표현을 해석해 기존 편집기·선택기를 여는 현재 기능이다. 임의의 자연어 문맥 추론을 뜻하지 않는다.
- **AI 서비스 호출**: 모델이 등록된 서비스를 선택하는 현재 기능이다. 현재 6개 조회/변경안 서비스이며, 쓰기는 별도 확인 후 기존 서비스가 수행한다.
- **미연결**: 기존 기능이 있어도 해당 대화 흐름에는 연결되지 않았다.
- **미구현**: 현재 제품에서 그 동작을 제공하지 않는다.

완료 여부는 시나리오 단위로 판단한다. **코드 확인 / 자동 검사 / 실제 API·DB / 실제 모델 / 실제 브라우저 전체 흐름**을 각각 기록한다. 일부 단계 검증은 전체 완료가 아니다. 아래 현황의 실제 검증은 후술한 교육용 계정의 시험 범위만 뜻한다.

## 실제 검증과 연결

현재까지 다음 **부분 기능**에 실제 교육용 DB·모델·브라우저 근거가 있다. 이 근거를 위의 새로운 대화 전체 흐름 완료로 확대하지 않는다.

| 근거 | 연결되는 시나리오 | 확인한 범위와 한계 |
|---|---|---|
| 실제 comments 변경·충돌 차단·원복·이력 | M01, R02 | 기존 API/서비스 경로. 모든 속성·대화 표현 검증 아님 |
| 실제 합성 용어 등록·개정·비활성·이력 3건 | M04, M05, O06 | 실제 저장 서비스와 브라우저 이력 확인. AI의 자유 문장 전체 편집 검증 아님 |
| 실제 6개 Tool 호출·연결안·적용·원복 | M06, O01, R01, R02 | 기존 활성 Source 하나, 실제 모델. 신규 Source/Callback 생성 아님 |
| 서비스 이름 없는 준비/옵션 질문 2건 | O01 | 실제 모델의 관련 서비스 선택. 임의 질문의 전체 성공률 아님 |
| 정확·별칭/Oracle Text 검색, 두 AU SQL 실행 | O02, O05 | 별도 API/SQL 경로의 실제 결과. 설정 도우미에서 조회까지 잇는 브라우저 전체 흐름 아님 |
| 대화창·선택기·분석 전 확인·모바일 화면 | C03, M01, M06, R01 | 실제 화면 조회/편집 전 확인. 모든 대화 쓰기 전체 실행 아님 |

세부 근거는 [서비스 Tool 검증 범위](service-tools.md#검증-범위)와 교육 산출물의 `lab/08-menu-service-verification.md`에 있다. 계정/권한 생성, 새 Agent 생성·실행, ORDS 공개, Scheduler 실행은 앞선 실제 변경 시험에 포함하지 않았다. 종료한 DDS 사용자의 Native Select AI 직접 호출 오류 조사는 이번 목록으로 재개하지 않는다.

## 보완 순서와 완료 기준

### 1. 프로파일 한 개를 대화로 완성

대상: C01~C05, M02, O02, R01~R02. 첫 번째 완료 시나리오다.

1. “업무 조회용 프로파일 만들어” → 이름 질문. 기존 대상 프로필을 먼저 선택하도록 막지 않는다.
2. “테이블 뭐 있어?” → 실제 접근 가능한 목록. “첫 번째와 세 번째”의 선택을 해당 목록 ID에 연결한다.
3. “이 모델 써” → 제공자·모델·Credential 참조 확인. 도우미 모델은 그대로 유지한다.
4. “테이블 하나 빼고 이름 바꿔” → 누적 초안과 선택 표시 갱신.
5. 최종 이름·객체·모델·설정·SQL을 한 변경안으로 검토하고 명시적 적용.
6. 생성값·이력 재조회. 생성만 확인한 상태와 실제 질문 실행 성공을 나눠 표시한다.
7. 별도 실행 확인 후 대표 질문의 SQL/결과를 독립 기대값과 비교한다.

인수 조건: 화면 이동 없이 완료, 같은 초안의 선택 유지, 설명만 요청/취소 시 쓰기 0회, 없는 객체·이름 중복·만료/재사용·동시 변경 차단, 실패 후 중복 생성 0회. 실제 DB·모델과 PC/모바일 브라우저 전체 흐름을 확인해야 완료다. 모델/인증 사전 확인과 실제 모델 호출 성공도 따로 기록한다.

### 2. 바뀐 업무 기준을 질문 결과에 반영

대상: M03~M07, O03~O05. “새 업무 용어 추가” → 기존 후보 검색 → 정의/별칭/참고 기준 입력 → 기존 소스 활용 또는 신규 구성 → 질문 재실행 → SQL·검색 근거·기대 결과 비교. 용어 저장 성공과 검색/SQL 반영 성공을 따로 확인한다.

### 3. 운영 변경을 추적하고 복구

대상: C06, M08, O06, R03~R04. “기존 구성 복사/수정” → 영향 비교 → 시험 질문 → 적용 → 이력 조회 → 이전 값으로 새 변경안. 영속 재개는 별도 설계 후 구현하며, 현재 새로고침 유지 기능이 있다고 표시하지 않는다.

### 4. 담당자가 다른 작업 연결

대상: C07, O07~O10. 계정/권한·DDS·APEX/OCI·Agent·Scheduler/ORDS를 각각 세부 시나리오로 나눈다. 기존 일반 사용자 세션을 관리자 세션으로 바꾸지 않고, 담당 단계 완료 뒤 원래 사용자 관점에서 재검증한다.

## 시나리오별 기록 양식

각 보완 작업은 아래 항목을 채우고 이 문서의 해당 행에 근거를 연결한다. 대화 시나리오 하나를 독립적인 완료 단위로 삼는다.

| 항목 | 기록할 내용 |
|---|---|
| ID·목표 | 위 목록의 ID, 사용자가 얻을 실제 결과 |
| 대화 | 기본 흐름, 빠진 값 질문, 중간 수정·취소·실패·재개 예시 |
| 입력·실행 주체 | 대상·현재 로그인 신원·필수값·권한·외부/유료 호출 |
| 상태·화면 | 선택 목록·초안·변경안·확인 대기·적용 결과가 바뀌는 순서 |
| 재사용 서비스 | 기존 Java 메서드, 등록 Tool 계약, 미리보기/적용/재조회/이력 경로 |
| 빠진 기능 | 기존 기능의 대화 연결 누락 / 새 기능 필요 / 선행 조건 / 실제 미검증 구분 |
| 완료 근거 | 커밋, 자동 검사, 실제 모델/DB·브라우저 결과, 기대값·관찰값, 미검증 범위 |

현재 31개 시나리오를 관리한다. C01~C06의 대화 명령/선택기 연결과 C07의 ADMIN 안내, O11 화면 안내, R05 질문·작업 전환을 우선 보완했다. 기존 AI 6개 서비스의 등록 범위는 그대로이며 신규 생성 계획을 AI가 자유 문장으로 구성하는 기능은 포함하지 않는다. 구현과 실제 인수 검증의 완료 여부는 별도로 기록한다.
