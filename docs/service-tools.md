# 선택해서 사용하는 서비스 Tool

로그인 후 모든 화면의 **오른쪽 아래 → 설정 도우미**를 누르면 배경 화면을 계속 조작할 수 있는 대화창이 열립니다. 필요한 대상을 묻고 작업 영역에 설정·변경안·실행 결과를 표시합니다. 닫았다 열어도 같은 대화와 진행 작업을 유지하며, 다른 페이지로 이동하거나 새로고침하면 초기화합니다. 좁은 화면에서는 창 위의 **현재 작업 / 대화 보기**로 전환합니다. 기존 설정·업무 용어·이력 서비스를 사용하며 별도 저장소나 AI 프레임워크 설치는 필요하지 않습니다.

## 대화로 작업

- “대화 저장 켜기”, “comments 끄기”: 대상 프로필을 선택하고 변경 전후 비교 → 확인 → **적용**. 등록된 프로필 속성은 `model 변경`, `temperature 설정`처럼 요청한 뒤 값을 입력할 수 있습니다.
- “업무 용어 등록”: 용어 → 정의 → 별칭 → 참고 SQL·기준을 차례로 입력하고 변경안을 확인합니다. 오른쪽 편집기로도 수정할 수 있습니다. 참고 SQL은 실행하지 않습니다. 용어와 이력 저장소가 준비되어 있어야 합니다.
- “업무 용어 수정”: 기존 항목을 검색해 선택하고 편집합니다. 등록·수정은 기존 버전 검사와 용어/이력 동시 저장을 사용합니다.
- “이 프로필에 업무 용어를 연결해줘”: 실제 조회된 활성 Semantic Source 중 하나를 선택합니다. 기존 연결을 유지한 추가안을 확인한 뒤 적용합니다. 소스·콜백 자체 생성은 기존 관리 화면을 사용합니다.
- “변경 이력 조회”: 현재 프로필의 기록을 표시합니다. 저장 후에는 읽어서 확인한 결과와 조회 가능한 이력을 표시합니다. 이력 조회 실패와 저장 실패는 구분합니다.
- “취소” 또는 새 요청: 현재 변경안을 무효화합니다. 결과를 확인하지 못한 쓰기는 자동 재시도하지 않습니다.

위 요청은 제한된 명령 연결이며 일반 언어 모델의 전체 작업 계획 기능은 아닙니다. 해석이 필요한 요청은 **AI 분석** 작업으로 연결합니다. 모델이 필요한 경우에만 대화 안에서 별도 도우미 모델을 선택하고, 전송 내용·비용을 확인한 뒤 실행합니다. **서비스 Tool 사용 (선택)**을 켜면 모델이 필요한 조회 서비스를 선택하고 Java가 결과를 돌려줍니다. 선택하지 않으면 기존 단일 분석 요청을 사용합니다.

## 구현 계약

- 완료 조건: 기본값은 꺼짐. 선택한 경우 등록된 조회 Tool → 실제 서비스 결과 → 최종 설명/변경 제안을 연결하고 화면에서 호출 결과를 확인할 수 있음.
- 사전 조건: 소유자 계정 로그인, 대상 프로필, 별도로 선택한 AI 도우미 모델. 전송 내용과 호출 비용에 동의한 경우만 모델 호출.
- 유지 조건: 변경은 기존 변경 미리보기·별도 적용 확인·버전/선행 조건 검사·`ProfileEditService`의 전후 이력과 읽어서 검증을 사용.
- 차단 조건: 임의 SQL/메서드/스키마 실행, 모델의 승인, 중복 Tool 실행, 불명확한 JSON, 호출 한도 초과, 조회 실패 후 성공 설명으로 진행.

## 사용 순서

1. 오른쪽 아래 **설정 도우미**에서 질문을 입력합니다. 예: “변경하지 말고 대화 기록 설정과 이력 준비 상태를 확인해 줘.” 전체 진단은 기존 **시작 → 준비 상태**에서 확인합니다.
2. 대화에서 대상 프로필과 필요한 도우미 모델을 선택합니다. 업무 조회용 Semantic Source가 붙지 않은 별도 제어용 모델 프로필을 권장합니다.
3. **AI 분석** 영역에서 목적을 선택하고 **서비스 역할·입출력·업무 순서**를 확인합니다. **서비스 Tool 사용 (선택)**을 켜고 **분석 요청 확인**을 선택합니다.
4. **전송할 정보**에서 인스트럭션·Tool 명세·전송 범위와 최대 호출 수를 확인하고 동의 후 **분석 실행**을 선택합니다.
5. **서비스 호출 결과**에서 실제 조회를 확인합니다. 변경 제안이 있으면 작업 영역의 변경 전후 비교를 확인하고 별도로 적용합니다.

메뉴가 없다면 실행 중인 JAR에 해당 변경이 포함됐는지 확인합니다. 소스 커밋·검증 포트 반영과 다른 포트의 실행 앱 업데이트는 별도입니다. 페이지를 열거나 메뉴를 선택하는 것만으로 모델 호출·DB 변경은 실행하지 않습니다.

| 등록 Tool | 실제 서비스 | 범위 |
|---|---|---|
| `setup.inspectConfiguration` | `AiSetupService.diagnose` | 목적별 설정 진단 |
| `setup.inspectHistory` | `AiSetupHistoryService.diagnose` | 이력 저장소·감사·수집 준비 상태. 기록 원문 제외 |
| `profile.inspectOptions` | `DatabaseService.profiles`, 공통 작업 카탈로그 | conversation/comments/constraints의 저장값과 변경 후보 |
| `glossary.inspectStorage` | `BusinessGlossaryService.status/historyStatus` | 사전·Oracle Text·용어 이력 저장소 준비. 용어 본문 제외 |
| `semantic.listSources` | `SemanticContextService.status` | 실제 소스 이름·활성 상태·콜백 메타데이터. 콜백 실행 제외 |
| `semantic.previewAttachment` | `SemanticContextService.status`, `ProfileEditService.edit` | 활성 소스 하나를 기존 연결을 보존하며 추가하는 읽기 전용 변경안 |

앞의 다섯 Tool 입력은 빈 객체입니다. `semantic.previewAttachment`만 실제 목록에서 확인한 `source` 이름을 받습니다. 대상·로그인 신원·목적은 검토한 요청에서 서버가 고정합니다. 모델이 다른 대상이나 실행 주체를 지정할 수 없습니다. 각 Tool은 요청당 한 번, 최대 6개를 호출하고 최종 응답을 포함해 모델은 최대 7번 호출합니다. 실패는 자동 재시도하지 않습니다. 선택 기능을 사용하면 단일 분석보다 호출 비용과 대기 시간이 늘 수 있습니다.

서비스별 역할·사용 상황·입출력 Schema·예시·결과 렌더러와 업무 순서는 `src/main/resources/setup/service-tools.json`에서 함께 관리합니다. 같은 명세를 AI 인스트럭션과 화면 안내에서 사용합니다. Spring AI `FunctionToolCallback`과 서버의 `ToolContext`로 기존 Java 서비스를 직접 호출하며, 별도 MCP 서버나 모델 제공자 설정을 추가하지 않습니다. [설계와 재사용 경계](explanation/in-process-service-tools.md).

모델은 등록된 Tool을 최소 한 번 조회한 후 설명과 단일 변경 제안을 반환합니다. 모델 출력은 정형 JSON으로 엄격하게 검사하며 Java가 등록된 서비스로 전달합니다. DB의 Native Tool Calling 지원을 전제로 하지 않습니다. 조회 성공과 실제 실행 성공·업무 정답은 구분합니다.

Tool 요청은 `type/name/arguments` 형식을 요구합니다. 최종 답변은 `type=final` 형식 또는 기존 `explanation/action` 두 필드 형식만 허용합니다. 기존 형식도 실제 조회 완료 뒤에만 수용하고, 허용 작업·변경 후보·별도 적용 확인을 그대로 검사합니다. 중복 키·추가 JSON·추가 승인 필드·임의 SQL은 수용하지 않습니다.

모델은 `conversation=true`, `comments=true`, `constraints=true`와 기존 활성 Source 하나의 추가 연결을 제안할 수 있습니다. 소스 연결은 실제 조회·서버 측 변경안 생성 후에만 제안할 수 있으며 적용 때 활성 상태·버전을 다시 검사합니다. 앞의 대화 명령으로 연결한 속성 편집·용어 편집과 구분합니다. 계정/권한·Source 생성·OCI/APEX 설정은 기존 화면과 SQL 안내를 사용합니다. 전체 확장 방향은 [자연어 제어 설계안](natural-language-control-design.md), 화면 계약은 [대화형 작업 영역](explanation/conversation-workspace.md)을 참고하세요.

객체·배열 JSON 결과는 공통 필드 목록과 중첩 펼침으로 표시합니다. **원본 JSON**, **JSON 복사**, **JSON 내려받기**는 원문을 보존합니다. 큰 정수와 중복 필드를 생략하거나 반올림하지 않습니다. 250,000자·깊이32를 넘거나 JSON이 아닌 결과는 기존 원문 표시를 유지합니다. 프로필의 기존 타입별 입력·소스 선택기는 그대로 사용하며, 임의 JSON 전체를 편집하는 새 범용 폼은 이번 범위가 아닙니다.

Tool 조회 결과는 현재 응답/로그인 세션의 설명 근거이며 별도 영구 감사 기록을 만들지 않습니다. 실제 프로필 변경 이력은 기존 저장소에 남습니다. Credential 본문·업무 행 데이터·대화 기록 원문을 조회 Tool로 읽지 않습니다. 입력한 질문과 미리보기에 표시한 메타데이터 및 같은 범위의 후속 Tool 결과는 선택한 모델에 전송됩니다.

## 검증 범위

응답 형식·반복 호출·호출 한도 문제로 중단하면 중단 코드와 이미 완료한 조회만 표시하며 변경안은 남기지 않습니다. 모델 응답 원문이나 숨겨진 인증 정보는 오류 메시지에 포함하지 않습니다. 다시 시도하려면 새 미리보기와 전송 동의가 필요합니다.

코드·테스트 변경과 실제 모델/DB 검증 결과를 구분해 기록합니다. 모델이 설명을 생성했다는 사실만으로 서비스 연결·DB 변경 성공을 판정하지 않습니다.

2026-11-26 합성 계정에서 실제 DB·모델을 통한 `profile.inspectOptions` 호출과 한국어 최종 설명, 옵션을 생략한 기존 단일 분석을 확인했습니다. 전송 미동의·토큰 재사용 거절, 변경안 없음, 전후 프로필 값 동일을 확인했습니다. Chrome에서는 기본값 꺼짐·옵션 전환 시 동의 초기화·실제 조회 결과 표시·390px 화면을 확인했습니다. 이번 실제 모델 시험에서 변경 적용은 실행하지 않았습니다. 세 조회 서비스의 분기와 기존 편집 서비스 위임·변경 동의·버전 변경 차단은 자동 테스트로 확인했습니다. 다른 모델·환경의 응답 준수까지 보장하지 않습니다.

2026-11-27 확장은 정형 모델 응답과 합성 서비스 결과를 사용한 Java 테스트로 여섯 서비스의 실제 Spring ToolCallback 경로, 연결 보존·미등록/비활성 소스 차단·변경 재확인·동의·토큰 재사용·반복/잘못된 인자를 검사했습니다. 실제 프런트엔드 모듈·CSS와 합성 HTTP 응답을 사용한 Chrome 검사에서는 명세 표시·목적 선택·7회 호출 비용 동의·연결안 확인과 데스크톱/390px 배치, JSON의 원문 다운로드·갱신·숨김·SQL/일반 텍스트 복원을 확인했습니다. 이번 확장에서 유료 AI·실제 ADB 변경은 실행하지 않았습니다. 전날의 실제 모델 시험을 새 여섯 도구 전체의 운영 검증으로 간주하지 않습니다.

### 추가 실제 검증과 보완

같은 날 후속 검증에서는 별도 교육용 ADB의 합성 계정으로 실제 모델과 여섯 서비스 호출을 연결했습니다. 설정·이력·옵션·사전·소스 조회 → 실제 연결안 → 별도 동의 → 기존 편집 서비스 적용 → 읽어서 검증과 이력을 확인하고 원래 연결로 복원했습니다. 적용 미동의와 토큰 재사용도 거절됐습니다. 위 초기 확장의 합성 시험과 후속 실제 시험을 구분합니다.

이 과정에서 모델이 boolean 옵션 후보만 보고 시멘틱 연결 요청을 끝내는 응답을 재현했습니다. 검토한 질문을 수행할 사용자 요청으로 명시하고, 서비스 결과는 근거 데이터로 구분했습니다. 매 단계에 아직 호출하지 않은 서비스와 이어갈 작업을 전달하며, boolean 후보 제한이 소스 연결안을 막지 않도록 안내를 보완했습니다. 서버의 허용 목록·엄격한 JSON 검사·별도 적용 확인은 유지합니다.

실제 시험 모델은 OCI 경유 `openai.gpt-5.4-mini`, 성공 시험의 응답 상한은 **세션에만 2,048토큰**으로 지정했습니다. DB 프로필의 토큰 설정은 바꾸지 않았습니다. 상한을 명시하지 않은 초기 시험에서는 세 번째 응답이 JSON 형식 검사에 실패했고, 이후 시험에서는 옵션 요약만 반환한 사례도 있었습니다. 초기 응답 원문을 보관하지 않아 JSON 실패가 잘림 때문인지는 단정하지 않습니다. 모델·질문에 따른 형식 준수까지 보장하지 않으며, 실패 시 완료한 조회와 중단 코드를 확인하고 새 요청에서 동의 후 진행합니다.

메뉴·일반/ADMIN 조회 검사에서는 DDS 조회 선행 권한 부족과 시멘틱 이력 저장소 미설치를 서버 장애로 표시하던 응답을 수정했습니다. 시멘틱 이력에는 공통 기록 테이블 준비를 안내하며 불필요한 RDF 설치를 요구하지 않습니다. DDS 화면의 인라인 스타일은 기존 외부 공통 스타일로 대체했고, 일반 계정에 보이던 SCOTT 설치 금지 경고는 제한 계정에서만 표시합니다. 프로필 속성의 JSON도 공통 HTML 보기로 연결했습니다.
