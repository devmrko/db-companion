# DB Companion 首次使用指南

[English](GETTING-STARTED.md) · [한국어](GETTING-STARTED.ko.md) · [日本語](GETTING-STARTED.ja.md) · [界面指南](SCREEN-GUIDE.md)

普通用户查看某些历史或采集记录前，需要具有相应管理权限的数据库账户完成准备。先确认目标所有者和已记录的触发器安装者。`ADMIN`只是可能使用的账户，并非所有功能都必须使用的固定账户。

## 1. 确认连接

选择正确的 Wallet 和 TNS 服务，以实际 Oracle 账户登录。在**连接信息**中核对数据库、登录用户和所选模式，再进行更改。模式选择器只改变浏览范围，不切换登录账户，也不提升权限。请求管理员协助时，提供相同数据库/Wallet、目标模式和对象；不要分享密码。

## 2. 明确人员和顺序

| 人员 | 首先执行 |
| --- | --- |
| 普通用户 | 确认连接，浏览可访问对象和定义，使用已准备的 Select AI 配置文件。历史控件不可用或尚未安装时，请求设置。 |
| 已记录的触发器所有者或有相应权限的安装者 | 对每个目标表/视图检查并安装或更新元数据历史代码，启用采集，然后设置对象级历史访问。已有安装应由已记录的触发器所有者处理。 |
| 应用存储或其他采集器的所有者 | 按功能准备其存储、直接授权和采集 Job。配置文件由其所有者管理；SQL 缓存和 DDS 归档由各自采集设置的所有者负责。并非所有存储都由 `ADMIN` 创建。 |

安装与授权会更改数据库，且可能分别提交。负责人员应先检查界面预览及现有权限，再执行应用。

## 3. 按需设置元数据变更历史

这里记录表/视图/列注释和受支持 Annotation 的变更，不记录业务数据行的变更。授权人员按以下顺序操作：

1. 对现有目标，以已记录的触发器所有者登录**同一数据库**；对新目标，使用有相应安装权限的账户。在**表、视图与列**中选择目标模式。仅选择管理员模式不会获得权限。
2. 打开目标表/视图。多个目标可在**批量历史与权限设置**中选择配置文件的 `object_list` 并预览。配置文件只用于分组对象，不是独立历史存储。检查解析出的每个对象；跨模式目标应按模式分别处理。
3. 打开**检查安装**，查看共用程序包和目标触发器的有效性、状态、下一步及安装权限。按提示更新已识别的旧代码；缺少触发器时使用**安装并启用触发器**。未知或不兼容的代码需要人工检查。代码显示 **Ready** 并不代表采集已开启。
4. 对准备好的目标开启**历史管理**。在**批量历史与权限设置**中，为指定的现有数据库用户选择**允许查询历史**或**允许查询及收集开关**，并限定对象。后者只能切换已验证的现有采集器，不能安装或替换代码。核对范围后应用；不要默认选择**所有用户（PUBLIC）**。
5. 普通用户重新连接或刷新，检查目标的**变更历史**与状态。采集记录实际修改元数据的数据库用户；用户访问规则只决定谁能查看或切换采集，不筛选被记录的修改者。同一对象的设置由多个配置文件共享。

安装者归属、部分提交和委托权限范围参见[元数据历史访问](metadata-history-access.md)及[代码更新](metadata-history-upgrades.md)。

## 4. 区分不同的历史来源

| 来源 | 应当了解 |
| --- | --- |
| 元数据变更历史 | 已安装且启用的触发器记录受支持的注释/Annotation 变更。未安装与启用后没有新变更是两种状态。 |
| 应用保存的历史 | 明确保存的执行/问题记录和受支持的设置更改有各自的存储与范围。会话状态不是数据库持久记录；外部修改也未必会追溯记录。 |
| SQL 缓存归档 | 登录账户所有者明确注册表和 Oracle Scheduler Job，采集部分 Select AI 调用候选。轮询可能漏掉已从 `V$SQL` 消失的 SQL；游标统计不是完整执行审计。不保证自动清理。参见 [SQL 缓存归档](sql-cache-archive.md)。 |
| Oracle 审计 / DDS 归档 | 原始审计与可选 DDS 归档的覆盖范围和设置不同。归档不会自动启用原始审计，也无法找回已过期记录。数据库 Scheduler Job 在应用退出后继续运行。 |

保留期限取决于来源和配置；不要从空结果推断统一的保留天数。

## 5. 完成第一次有用的查询

确认连接，选择可用配置文件，查看相关业务术语和定义，再到 **Select AI 测试**生成 SQL。核对配置文件允许的对象、提示词/上下文和生成的 SQL 后，再明确执行查询。用可信业务答案验证结果；AI 审查只是解释，不是数值验证。生成或审查可能向配置的提供商发送问题、SQL 和所选上下文并产生费用；请求前检查发送内容及费用范围。用 AI 更改业务数据不是入门步骤。更多说明参见[界面指南](SCREEN-GUIDE.md)、界面的 **SQL ?**，以及单独的[可调用 AI](callable-ai.md)程序包流程。

## 快速排查

| 现象 | 检查 |
| --- | --- |
| 控件不可用 / 需要管理员设置 | 打开**设置说明**和**检查安装**，请已记录的安装者核对权限与目标状态。 |
| **MISSING** | 核对目标对象和程序包/触发器；安装是单独的授权操作。 |
| **READY** 但没有历史 | 检查**历史管理**已开启、登录账户有查询权限，并确认采集开始后有受支持的变更。 |
| `ORA-00942` / 访问检查 | 对象或视图可能不存在、不受支持或不可访问；请管理员检查直接授权和原始 ORA 代码。 |
| 记录或控件与预期不同 | 重查 Wallet、TNS、数据库、实际登录用户和目标模式。模式选择不会切换登录。 |
