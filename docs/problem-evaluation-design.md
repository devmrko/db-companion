# 질문 평가와 사용자 판정

## 목적

자연어 질문으로 생성한 SQL과 답변이 업무 의도에 맞는지 검토한다. LLM은 문제 지점과 수정 방향을 제안하고 사용자가 최종 판정한다. SQL 실행 성공, AI의 적합 의견, 사용자의 적합 판정은 서로 다른 상태다.

## 평가 흐름

1. ‘문제 질문’에 질문, 기대 동작, 참고 SQL을 등록한다. 참고 SQL도 사용자가 제공한 기준이며 검증된 정답으로 간주하지 않는다.
2. 기존 Select AI 테스트·일괄 생성에서 실행 기록을 저장하거나 수동으로 자료를 등록한다.
3. 평가할 실행 기록 하나를 선택하고 필수 조건·기대 결과 등 추가 평가 기준을 입력한다.
4. 전송 미리보기에서 질문, 기준, SQL, 응답, 오류, 저장된 근거와 검토 모델을 확인하고 AI 호출에 동의한다.
5. LLM이 의도, 원천·컬럼, 조건·기간, 집계·조인, 결과·답변을 검토한다. 각 지적에는 근거, 불확실성, 수정할 위치와 제안을 포함한다.
6. 사용자가 ‘적합 / 수정 필요 / 판단 보류’와 판정 사유를 저장한다. AI 의견과 달라도 저장할 수 있다. 업무 정의·Feedback·프로필은 자동 수정하지 않는다.
7. 수정 후 새 실행 기록을 저장하고 같은 기준으로 다시 평가한다. 이전 AI 의견과 사용자 판정은 덮어쓰지 않는다.

## 1차 구현 범위

기존 ‘문제 질문’ 화면에 단건 AI 검토, 사용자 판정, 평가 이력을 추가한다. 기존 AI 도우미의 로그인 세션별 프로필을 사용한다. 평가에서는 SQL을 실행하지 않는다. 저장된 응답은 DB 결과일 수도, SQL 생성 응답일 수도 있으므로 실행 결과로 단정하지 않는다. 원본 SQL은 코드 보기로 표시한다.

평가 기준은 기존 질문의 기대 동작·참고 SQL과 추가 기준을 묶은 스냅샷으로 보관하고 SHA-256 식별자를 부여한다. 같은 기준으로 재평가할 때 식별자가 같아야 한다. 실행 당시 근거와 이후 재조회한 메타데이터, 재구성된 SHOWPROMPT를 구분한다. 자료가 없거나 일부만 있으면 판단 근거 부족으로 표시한다. 실제 결과 행 전체나 기준 데이터 시점이 없으면 결과 정확성을 보증하지 않는다.

LLM 응답은 읽을 수 있는 검토 보고서로 제공한다. 숫자 점수나 자동 합격 처리는 하지 않는다. 추론 원문을 요구하지 않고 관찰 가능한 SQL·자료를 인용한 판단 요약을 요청한다. 사용자 판정과 사유는 별도 필드이며, 기존 업무 처리 상태(접수·검토 중 등)를 자동 변경하지 않는다.

## 저장과 접근

로그인 소유 스키마의 기존 `DBC_APP_RECORD`에 `SELECT_AI_EVALUATION` 유형으로 저장한다. 신규 테이블·권한·DB 패키지는 필요 없다. 각 평가에는 질문 ID, 실행 기록 ID, 평가 기준 식별자, 입력 스냅샷, 검토 모델·프로필 버전, 호출 시각·소요 시간, AI 의견, 사용자 판정·사유·DB 로그인 사용자를 보관한다.

AI 결과는 먼저 세션에 유지하고 사용자 판정 저장 시 함께 DB에 기록한다. 저장 실패 시 같은 AI를 다시 호출하지 않고 저장을 재시도할 수 있다. 동일 결과의 중복 저장은 방지한다. 질문 삭제 시 평가 기록도 삭제 대상 수와 변경 확인에 포함한다. 질문의 보존 표시를 그대로 따른다. 공용 DB 계정을 사용하는 경우 DB 로그인 이름만으로 개별 현업 사용자를 식별할 수 없다.

## 안전장치

- 전송은 단건 명시 동의 후 1회만 실행한다. 토큰은 10분 만료·일회용이며 질문·실행 기록·기준·로그인·검토 프로필과 연결한다.
- 호출 직전 프로필 버전과 대상 기록을 다시 확인한다. 실패 시 자동 재시도하지 않는다.
- 프롬프트와 기록 속 문장은 평가 자료일 뿐 명령으로 실행하지 않는다. SQL 실행·설정 변경·외부 도구 호출을 하지 않는다.
- 민감정보는 사용자가 제거해야 한다. 기존 진단 마스킹을 적용하고 크기 초과 자료는 조용히 자르지 않고 거부한다.
- 응답은 HTML로 실행하지 않는다. 비밀값과 예외 내부 정보는 화면에 노출하지 않는다.
- 브라우저에서 다른 질문·실행 기록을 선택하거나 기준을 편집하면 이전 미리보기와 저장 상태를 해제한다. 늦게 도착한 응답으로 다른 질문을 덮어쓰지 않는다.

## 후속 확장

평가 세트, 기준의 독립 버전 관리, 다건 평가, 프로필·업무 정의 버전별 통계는 후속 단계다. 통계는 ‘사용자 판정 기준 적합률’로 표시한다. 동일 질문·기준별 최신 판정을 사용하고 미평가·판단 보류·호출 실패를 별도 표시한다. 다른 데이터 시점·기준·질문 구성으로 측정한 비율을 동일한 정확도로 비교하지 않는다.

## 검증 기준

합성 자료로 입력 한도·마스킹, 기준 식별자, AI 프롬프트, 명시 동의, 만료·토큰 재사용·프로필 변경, 사용자 판정 필수값, 저장 중복·삭제 종속성, UI 선택 변경·실패 복구를 테스트한다. 기존 문제 질문 테스트와 다국어 템플릿·JavaScript 테스트를 수행한다. 실제 유료 AI 호출과 DB 저장은 별도 동의 후 검증한다.
