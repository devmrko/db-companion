# DB Companion 첫 사용 가이드

[English](GETTING-STARTED.md) · [简体中文](GETTING-STARTED.zh-CN.md) · [日本語](GETTING-STARTED.ja.md) · [화면 가이드](SCREEN-GUIDE.md)

일부 이력·수집 기능은 일반 사용자가 기록을 보기 전에 필요한 관리 권한이 있는 DB 계정에서 준비해야 합니다. 대상 소유자와 기존 트리거 설치자를 먼저 확인하세요. `ADMIN`은 가능한 계정 중 하나이지 모든 기능의 고정 필수 계정이 아닙니다.

## 1. 접속 대상 확인

올바른 Wallet과 TNS 서비스를 고르고 실제 Oracle 계정으로 로그인합니다. **접속 정보**에서 DB, 로그인 사용자, 선택한 스키마를 확인한 뒤 변경 작업을 시작하세요. 스키마 선택은 탐색 범위만 바꾸며 로그인 계정이나 권한을 바꾸지 않습니다. 관리자에게 설정을 요청할 때는 같은 DB/Wallet과 대상 스키마·객체를 알려 주세요. 비밀번호는 공유하지 마세요.

## 2. 역할과 순서

| 담당 | 먼저 할 일 |
| --- | --- |
| 일반 사용자 | 접속을 확인하고 접근 가능한 객체·정의를 탐색하며 준비된 Select AI 프로필을 사용합니다. 이력 설정이 비활성화되거나 설치가 빠졌으면 설정을 요청합니다. |
| 기록된 트리거 소유자 또는 필요한 권한을 가진 설치자 | 대상 테이블/뷰별 메타데이터 이력 코드를 확인·설치·업데이트하고 수집을 켠 다음 객체별 이력 접근을 설정합니다. 기존 설치는 기록된 트리거 소유 계정을 사용합니다. |
| 앱 저장소·기타 수집 기능의 소유자 | 기능별 저장소, 직접 부여된 권한, 수집 Job을 필요에 따라 준비합니다. 프로필은 소유자가 관리하고 SQL 캐시·DDS 보관소는 각 수집 설정의 소유 계정에 둡니다. 모든 저장소를 `ADMIN`이 만드는 것은 아닙니다. |

설치와 권한 부여는 DB를 변경하며 별도로 커밋될 수 있습니다. 담당자는 UI 미리보기와 현재 권한을 검토한 뒤 적용하세요.

## 3. 필요한 경우 메타데이터 변경 이력 준비

이 기능은 테이블/뷰/컬럼 코멘트와 지원되는 Annotation의 변경을 기록합니다. 업무 데이터 행의 변경 이력은 아닙니다. 권한 있는 담당자는 다음 순서로 진행합니다.

1. 기존 대상은 기록된 트리거 소유자로, 새 대상은 적절한 설치 권한 계정으로 **같은 DB**에 로그인합니다. **테이블·뷰·컬럼**에서 대상 스키마를 선택합니다. 관리자 스키마를 선택하는 것만으로 권한이 생기지 않습니다.
2. 대상 테이블/뷰를 엽니다. 여러 대상은 **이력 일괄·권한 설정**에서 프로필의 `object_list`를 선택해 미리봅니다. 프로필은 대상 묶음이지 별도 이력 저장소가 아닙니다. 확인된 객체를 검토하고 다른 스키마는 스키마별로 처리합니다.
3. **설치 확인**에서 공통 패키지와 대상 트리거의 유효성, 상태, 다음 작업, 설치 권한을 확인합니다. 알려진 구버전 코드는 표시된 순서로 업데이트하고 트리거가 없으면 **트리거 설치·켜기**를 사용합니다. 알 수 없거나 호환되지 않는 코드는 수동 검토가 필요합니다. 코드가 **Ready**여도 수집이 켜졌다는 뜻은 아닙니다.
4. 준비된 대상에서 **이력 관리**를 켭니다. **이력 일괄·권한 설정**에서 특정 기존 DB 사용자에게 **조회 허용** 또는 **조회·수집 ON/OFF 허용**을 대상별로 설정합니다. 후자는 검증된 기존 수집기의 ON/OFF만 바꾸며 코드 설치·교체는 못 합니다. 범위를 확인해 적용하고 **전체 사용자 (PUBLIC)**를 기본값으로 선택하지 마세요.
5. 일반 사용자는 재접속하거나 새로고침한 뒤 대상의 **변경 이력**과 상태를 확인합니다. 수집은 메타데이터를 실제 변경한 DB 사용자를 기록합니다. 사용자별 설정은 누가 조회하거나 ON/OFF를 관리하는지만 정하며 기록할 변경자를 걸러내지 않습니다. 같은 객체의 설정은 프로필 간에 공유됩니다.

설치자 소유권, 부분 적용, 위임 범위는 [메타데이터 이력 접근](metadata-history-access.md)과 [코드 업데이트](metadata-history-upgrades.md)를 참고하세요.

## 4. 서로 다른 이력 구분

| 출처 | 확인할 점 |
| --- | --- |
| 메타데이터 변경 이력 | 설치·활성화된 트리거가 지원되는 코멘트/Annotation 변경을 기록합니다. 미설치와 활성화 후 변경이 없는 상태는 다릅니다. |
| 앱 저장 이력 | 명시적으로 저장한 실행/문제 질문 자료와 지원되는 설정 변경은 각 저장소와 범위를 가집니다. 세션 상태는 DB 영속 기록이 아니며 외부 변경이 소급 기록되지는 않을 수 있습니다. |
| SQL 캐시 보관 | 로그인 소유자가 테이블과 Oracle Scheduler Job을 명시적으로 등록해 일부 Select AI 호출 후보를 수집합니다. `V$SQL`에서 사라진 SQL은 놓칠 수 있고 커서 통계는 전수 실행 감사가 아닙니다. 자동 삭제도 보장하지 않습니다. [SQL 캐시 보관](sql-cache-archive.md)을 보세요. |
| Oracle 감사 / DDS 보관 | 원본 감사와 선택적 DDS 보관은 범위와 설정이 다릅니다. 보관은 원본 감사 정책을 자동 설정하거나 만료된 기록을 복구하지 않습니다. DB Scheduler Job은 앱 로그아웃 후에도 실행됩니다. |

보존 기간은 출처와 설정에 따라 달라집니다. 빈 화면만으로 보편적인 보존 일수를 추정하지 마세요.

## 5. 첫 조회 성공 경로

접속을 확인하고 사용할 수 있는 프로필을 선택한 뒤 관련 비즈니스 용어와 정의를 살펴봅니다. **Select AI 테스트**에서 SQL을 생성하고 프로필 대상 객체, 프롬프트·참고정보, 생성 SQL을 검토한 다음 명시적으로 조회를 실행합니다. 결과는 신뢰할 수 있는 업무 기준과 대조하세요. AI 검토는 설명이지 수치 검증이 아닙니다. 생성·검토 요청은 질문, SQL, 선택한 문맥을 설정된 제공자에게 전송하고 비용이 발생할 수 있으므로 전송 범위와 비용을 먼저 확인하세요. AI로 업무 데이터를 변경하는 것은 입문 절차가 아닙니다. [화면 가이드](SCREEN-GUIDE.md), 화면의 **SQL ?**, 별도 패키지 기능인 [Callable AI](callable-ai.md)를 참고하세요.

## 빠른 문제 해결

| 증상 | 확인 |
| --- | --- |
| 버튼 비활성화 / 관리자 설정 필요 | **설정 안내**와 **설치 확인**을 열고 기록된 설치자에게 권한과 대상 상태 확인을 요청합니다. |
| **MISSING** | 대상 객체와 패키지·트리거를 확인합니다. 설치는 별도 권한 작업입니다. |
| **READY**인데 이력이 없음 | **이력 관리** ON, 로그인 계정의 조회 권한, 수집 시작 후 지원되는 변경이 있었는지 확인합니다. |
| `ORA-00942` / 접근 검사 | 객체·뷰가 없거나 미지원 또는 접근 불가일 수 있습니다. 관리자가 직접 권한과 원래 ORA 코드를 확인해야 합니다. |
| 예상과 다른 기록·버튼 | Wallet, TNS, DB, 실제 로그인 사용자, 대상 스키마를 다시 확인합니다. 스키마 선택은 로그인을 바꾸지 않습니다. |
