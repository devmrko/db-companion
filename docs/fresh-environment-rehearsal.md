# 빈 ADB에서 첫 자연어 조회와 결과 보관까지

새 ADB와 빈 전용 계정에서 가상 데이터를 준비하고 업무 용어를 연결해 조회한 뒤, 다시 로그인하여 당시 결과를 여는 절차다. 최초 모델 인증·프로파일은 ADMIN/OCI 담당자와 사용자가 준비한다. 도우미가 사용할 모델이 없는 상태에서 AI 대화로 자체 설치를 시작할 수는 없다.

3시간 교육 전에 DB 실행·접속 IP·Wallet·Java/SQLcl·앱과 ADMIN/OCI 담당자를 준비한다. APEX DDS를 포함하면 APEX26.2 이상·업그레이드 완료 상태도 사전 확인한다. 새 ADB의 기본 APEX가 요구 버전보다 낮으면 제공된 업그레이드 작업을 수업 전에 끝내야 한다. 클라우드 패치 대기를 참가자의 대화·조회 실습 시간에 포함하지 않는다.

## 참가자 순서

1. OCI에서 ADB `AVAILABLE`과 현재 접속 IP 허용 여부를 확인한다. Wallet·TNS를 선택해 DB Companion에 로그인하고 **접속 정보**에서 DB·계정·스키마를 대조한다. DB가 정지돼 있으면 먼저 시작한다. 네트워크 시간 초과를 AI 응답 오류로 해석하지 않는다.
2. ADMIN이 **계정 생성·권한 설정**에서 새 전용 계정을 준비한다. 필요한 권한을 미리보기로 검토한다. 데이터 생성에는 자기 스키마의 CREATE TABLE과 quota가 필요하다. 이후 권한은 기능별로 추가한다.
3. 전용 계정의 **실습 데이터 준비**에서 상황·질문·규칙·기간·행 수·접두어를 넣고 프롬프트와 비밀번호 없는 설정을 받는다. [로컬 실행 안내](scenario-data.md)에 따라 Codex가 SQL을 작성하고 검토한 뒤 지정 SQLcl 래퍼로 실행한다. 실제 객체명이 `LAB_ACTIVITY`라면 이후 예제의 `ACTIVITY`를 그대로 사용하지 않는다.
4. 테이블 수·행 수·PK/FK·중복·제외·기간 경계와 기준 SQL의 계산값을 확인한다. 오류가 나면 실제 남은 객체와 실패 단계를 확인한다. 테이블 생성과 데이터 입력 전체를 재실행하지 않는다.
5. **인증 정보의 Select AI 시작 안내**에서 Resource Principal 준비 SQL과 OCI IAM 정책을 확인한다. DB ADMIN은 사용할 사용자에게 활성화하고, OCI 담당자는 **이번 ADB**의 지정 구획·모델 호출을 허용한다. 이전 ADB ID에만 한정된 정책은 새 ADB에 적용되지 않는다. Credential 이름이 보이거나 프로파일 생성이 성공해도 실제 호출 성공은 별도다.
6. 소유자가 프로파일 변경 이력 저장소를 준비하고 최초 도우미 프로파일을 생성한다. 객체·제공자·모델·리전·구획·Credential 참조를 검토한다. 작은 실제 호출로 확인한다. API Key·비밀번호를 프롬프트에 넣지 않는다.
7. **업무 용어 사전**에서 사전 테이블과 공통 기록 저장소를 준비한다. Oracle Text 설치 전에 ADMIN의 CTXSYS.CTX_DDL 실행 권한을 확인한다. 설치 SQL을 검토해 형태소 분석 정책·인덱스를 만들고 업무 용어·별칭·SQL 기준을 등록한다.
8. 공통 기록 저장소가 있지만 운영 배포 버전이 없으면 사전 검색·SQL 생성이 보호될 수 있다. 개발 실습은 **시멘틱 배포 → 개발 모드(현재 설정)**를 명시적으로 선택한다. 운영 배포 보호를 전역으로 해제하지 않는다.
9. **업무 용어 검색 함수**에서 코드·사전·Oracle Text 상태를 확인하고 설치·시험한다. **Semantic Context** 관리에는 별도의 DBMS_AI_SEM 실행 권한이 필요하다. ADMIN이 해당 화면의 사용자 권한 미리보기로 실제 발견한 패키지 소유자를 확인하고 부여한다.
10. 소유자가 CUSTOM global Source를 생성하고 콜백 함수에 연결한다. Source 생성과 콜백 설치 이력을 확인한다. 사전 검색 성공과 프로파일의 Source 연결은 별도 단계다.
11. 오른쪽 아래 **설정 도우미**에서 도우미 모델과 전송 동의를 선택한다. 예: “기존 프로파일을 복제하자” → 이름·테이블 수정 → 생성안 → 별도 적용 → 생성값·이력 확인. AI는 등록된 서비스로 실제 목록·설정을 확인하며 DB 변경은 기존 검토·적용 서비스를 사용한다.
12. 생성한 프로파일을 대상으로 업무 용어 Source를 연결한다. **질문으로 확인**에서 질문을 입력하고 전송 내용 확인 → SQL 생성 → 생성 SQL 확인 → 별도 실행을 진행한다. 값은 기준 SQL·가상 데이터의 기대값과 대조한다.
13. 결과 아래 **결과 보관**을 선택한다. **실행 이력 → 보관한 조회 결과**를 열어 질문·SQL·결과 표를 확인한다. 새로 로그인해도 저장된 표는 유지된다. [보관 범위와 한계](select-ai-result-history.md)를 확인한다.

## 새 환경에서 실제 확인한 것

2026-11-27~28 별도 교육용 ADB 26ai, DB 구성요소 23.26.4.1.0, SQLcl 26.3.1, OCI 모델 `openai.gpt-5.4-mini`로 확인했다. 모든 모델·리전·업무의 성공을 보장하는 시험은 아니다.

| 단계 | 실제 결과 |
|---|---|
| 최초 준비 | 빈 계정·기존 도우미 모델 0건 확인 후 프롬프트 내보내기부터 시작 |
| 데이터 | 가상 게임 2건·활동 12건. 기준 질문 10개와 PK/FK·기간 검사. 생성한 검증 SQL의 ORA-00937은 읽기 전용 집계식만 수정하고 검증 재실행 |

공백·조사를 처리하더라도 광범위한 색인 후보만으로 정의를 첨부하지 않는다. 후보 검색 뒤 등록 표현의 전체 일치를 Oracle Text로 확인한다. 한국어 명사 단독 검색과 질문의 실제 활용형이 다를 때는 실제 표현으로 다시 확인하고 Oracle이 표시한 구간을 검사한다. 이 활용형 재확인 SQL을 UI 검색과 DB 설치용 사전 API에서 공통으로 사용한다.

## DDS·APEX·MCP는 별도로 확인

위 표는 소유자 경로와 도우미·결과 이력, 새 ADB의 실제 SQLcl MCP 최종 사용자 DDS 검증이다. 처음부터 IAM 도메인·사용자를 새로 만드는 시험과는 구분한다. 이번에는 기존 교육용 도메인·A/B 사용자·그룹을 재사용하고 새 ADB에 신뢰와 행 정책을 구성했다.

새 ADB의 최초 APEX는 26.1.6이었으며 APEX DDS에는 26.2 이상과 Social Sign-In 등 별도 준비가 필요하다. MCP 성공을 APEX 경로 완료로 해석하지 않는다. 직접 DB 로컬 DDS 사용자의 Native Select AI 호출에 남은 ORA-01435/16963은 앞서 종료한 조사 범위이며 여기서 해결했다고 주장하지 않는다.

### APEX를 처음 설치할 때 확인할 점

이번 새 환경은 EARLY 전환 후 실제 제공된 APEX26.2.1 업그레이드를 실행하고 `UP-TO-DATE`를 확인했다. 배포한 Workspace 생성·개발자 등록·Import SQL로 새 앱과 지원 테이블8개를 설치했다. 공식 앱의 공통 프로시저가 DBMS_CLOUD_AI_AGENT도 참조하므로 이 패키지의 실행 권한을 Import 준비 SQL에 추가했다. ADMIN 설정 후 소유자 객체를 재컴파일해 오류·무효 객체0건을 확인했다. 이것은 Agent 업무 실행 시험과 구분한다.

공식 앱의 최초 관리자 설정 창에서 `Skip`을 선택하면 현재 사용자를 앱 관리자로 저장한다. DDS 교육용 A/B의 첫 로그인 전에 소유자가 앱 설정을 초기화해야 한다. 이 실습의 A/B는 최종 사용자이며 앱 설정은 소유자 SQL·DB Companion으로 관리한다. 고객의 APEX 관리용 SSO 계정·접근 규칙을 구성한 시험은 아니다. 새 OAuth 앱의 첫 로그인에는 `profile` 정보 접근 동의 화면이 나타날 수 있으므로 대상 앱·사용자·Scope를 확인한다.

`DEEP_SEC_IS_ENABLED`는 같은 SQL 세션에서 먼저 `APEX_UTIL.SET_WORKSPACE`로 대상 Workspace를 선택한 뒤 확인한다. Workspace가 없는 관리 세션의 값으로 앱의 DDS 활성 여부를 판정하지 않는다.

새 앱의 실제 OCI IAM A→B→A도 완료했다. 세 번의 생성 SQL이 동일했고 지역별 별도 조건을 넣지 않았다. A의 EU AU2·행1~6 → B의 APAC AU3·행7~10 → A의 EU AU2·행1~6과 일치했다. 모든 단계에서 `CURRENT_USER`·`SESSION_USER`는 `XS$NULL`, 최종 사용자 신원은 해당 IAM 사용자였다. B가 A의 질문 ID로 결과를 열면 ORA-01403으로 차단됐다. 데스크톱 실제 결과 화면을 확인했다.

이 경로는 고정 프로파일의 소유자 함수가 SQL 텍스트만 생성하고, APEX 페이지의 최종 사용자 DDS 컨텍스트에서 조회하는 호환 방식이다. DDS 사용자가 네이티브 Select AI·Semantic Source를 직접 호출하는 경로의 해결이나 고객 AD/LDAP 연계, 새 VM 설치, APEX 관리용 SSO UI 검증을 뜻하지 않는다. 원본 앱 export와 지원 테이블은 보존하고 별도 교육 앱 메타데이터에 호환 패치를 적용했다. 최초 패치 재설치의 클라이언트240초 제한 후 앱·12행 데이터·지원 테이블8개를 재조회하고, 같은 패치를 지원 객체·Credential 재설치 없이 더 긴 제한으로 완료했다.
