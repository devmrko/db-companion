# 실습 데이터 준비

빈 실습 스키마에서 시작하는 사용자가 업무 상황과 질문을 입력하고, Codex에 전달할 프롬프트를 복사한다. Codex가 DDL·합성 데이터·검증 SQL을 작성하고 SQLcl로 실행한 뒤, 같은 객체를 메타데이터·용어·프로필 설정에 사용한다.

기존 Scott 설치 기능은 고정 예제다. 이번 경로는 사용자의 업무 상황에 맞는 예제를 만드는 별도 읽기 전용 안내다. 기존 세션·공통 UI·HTTP/CSRF 유틸리티를 재사용하며, 새 의존성·자동 DB 변경·AI 호출을 추가하지 않는다.

- `/db/demo-data`: 유일한 실습 데이터 메뉴다. 기존 단계형 화면에서 로그인 소유자, 등록 Wallet/TNS, 업종 프리셋·업무 상황·질문·규칙·시작일/종료일·행 수(1~10,000)·접두어를 지정하고 파일 검토로 이동한다.
- `/db/scenario-data`: 이전 링크를 `/db/demo-data`로 리다이렉트한다. 중복 화면·서비스는 두지 않는다.
- `/db/demo-data/aliases`: 기존 Wallet/TNS 목록 서비스를 재사용한다. DB에 접속하지 않는다.
- `/db/demo-data/prompt`: `DemoDataPrompt`의 기존 전용 계정·동일 스키마·업무 조건 검증 후 프롬프트와 비밀번호 없는 JSON을 반환한다. ADMIN 등 관리 계정과 선택 스키마가 다른 경우 생성하지 않는다. 대상 계정은 클라이언트 입력이 아닌 세션에서 정한다.
- 프롬프트는 실제 DB·계정 확인, 기존 객체 확인, 생성 SQL 검토, 파일별 실행, 독립적인 기준값 대조를 요구한다. 비밀번호·Wallet 내용은 포함하지 않는다.
- 출력은 DDL, 적재, 검증 SQL과 업무 정의·기대 결과다. Select AI 프로필이나 DDS 정책은 데이터 검증 뒤 별도로 구성한다.
- 기존 객체는 같은 접두어라도 수정·삭제하지 않는다. 충돌이나 부분 실패 시 중단하며 전체 자동 재실행은 하지 않는다. 업무 정답 COMMENT·Annotation은 후속 실습까지 남겨 두고, 업무 규칙 파일에 초안을 기록한다.
- `scripts/scenario/sqlcl.sh`와 Python 표준 라이브러리 래퍼만 접속에 사용한다. 저장소 밖 비밀 파일의 소유자·권한·링크/macOS ACL·선택 대상 일치를 확인하고 SQLcl 표준입력으로 비밀번호를 전달한다. 래퍼는 SQL 샌드박스가 아니며 검토와 최소 권한이 필요하다.
- 번역은 `feature-demo-data.json` 한 파일에 모으고 main의 기존 번들 내용·순서를 유지하며 새 키만 추가한다.
- 검증: 가상 Wallet·가짜 SQLcl·입력 한도·소유자 경계·출력 계약·4개 언어 렌더링·복사/다운로드·Java/JS/PMD/공개본 검사. 실제 로그인·SQLcl·DB 생성·업무 정답은 이 통합 변경에서 실행하지 않는다.

계정 준비와 사용 절차는 [상세 안내](scenario-data.md)와 [영문 안내](scenario-data.en.md)를 따른다.
