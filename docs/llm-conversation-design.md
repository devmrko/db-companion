# LLM이 받는 설정 대화

사용자는 입력 중에도 추천·설명·다른 작업을 요청할 수 있다. 모든 자유 입력을 LLM에 전달하고, LLM은 메뉴 설명과 서비스 계약을 참조해 조회 서비스를 선택한다. 기존 정규식 명령 분류기는 이 경로에서 사용하지 않는다.

대화를 시작할 때 도우미 모델과 전송·사용량 동의를 한 번 선택한다. 선택한 모델이 바뀌거나 설정 버전이 달라지면 다시 선택한다. 질문, 현재 작업·초안, 최근 대화와 선택한 서비스의 메타데이터를 해당 모델에 보낸다. 비밀번호·키·행 데이터는 입력 자료에 포함하지 않는다. 대화 기록은 로그인 세션 메모리에만 보관한다.

기존 Java 서비스에 입력·출력 설명을 가진 Tool 어댑터를 연결한다. 별도 MCP 서버는 만들지 않는다. 조회 Tool은 결과를 LLM에 돌려주고, 작업 영역 Tool은 모델이 작성한 안내와 서버가 검증한 계획을 화면에 직접 반환한다. 작업 영역 Tool 뒤에는 추가 모델 호출을 하지 않는다. 일반 답변은 텍스트 또는 최종 JSON으로 받되, 그 안에 임의로 붙인 작업 지시는 실행하지 않는다. 실제 호출한 작업 영역 Tool이 만든 계획 하나만 화면에 반영한다. 화면 작업은 초안 수정·기존 화면의 조회·변경안 표시까지만 수행한다. DB 변경·SQL 실행은 기존의 별도 확인, 토큰, 버전 검사, 이력 저장, 결과 재조회 절차를 따른다.

생성 대화에는 현재 단계와 초안을 제공한다. “뭘로 넣는 게 좋아?”에는 현재 입력 항목을 기준으로 추천하고, “그걸로 해”는 직전 추천을 참조해 초안을 수정한다. 설명만 요청한 경우 초안은 유지한다. 모델이 임의 메서드·SQL·권한 변경을 실행할 수 없다. Tool 호출 횟수와 입력 크기를 제한하고 실패 시 자동 재시도하지 않는다.

추천은 `creation.suggest`로 한 후보를 구조화해 보관하며 `creation.updateDraft`와 구분한다. 최근 추천을 명시적으로 전달하고 제안 반영 버튼도 제공한다. 목록 조회와 테이블 선택은 별도 Tool이다. `admin.advice`는 기존 권한 안내 서비스의 실제 SQL·검증 SQL을 반환하며 현재 권한이 확인됐다고 표현하지 않는다. 메뉴·서비스 명세는 `/ai-setup/conversation/catalogue`와 대화 설정의 펼침 항목에서 확인한다.

단계·초안 외에 화면에 표시한 객체 후보(최대 40개와 일부 여부), 모델·리전·Credential 이름 후보를 문맥에 포함한다. 실제 Credential 내용은 포함하지 않는다. 제공자 응답의 JSON 문자열 안 줄바꿈은 값이 바뀌지 않도록 처리한다. 단일 JSON 코드 블록도 해석할 수 있지만 중복 키와 임의 작업은 거부한다. 읽기/작업 요청 뒤에 모델이 이어 쓴 가짜 관찰은 사용하지 않고 실제 서비스 반환값만 기록한다.

서비스를 한 번도 호출하지 않고 첫 답변을 끝내려 하면, 요청을 실제로 수행했는지 모델이 한 번 재검토한다. 설명·확인 질문만 필요한 경우는 그대로 답할 수 있고, 실제 표시·조회가 필요한 경우 등록 Tool을 선택하도록 한다. 이 검토도 원래 메시지의 최대 7회 호출 안에 포함한다. 실패한 DB 변경이나 결과를 모르는 외부 호출을 자동 재실행하는 절차는 아니다.

## 기존 업무 정의 변경과 오류 확인

“업무정의를 좀 바꿀까 하는데?”처럼 대상이 불명확하면 어떤 정의인지 확인하거나 기존 정의 선택으로 이어간다. 신규 용어 등록은 명시적인 추가 요청에만 사용한다. 기존 용어 검색·수정은 `workspace.glossaryList`의 선택 입력 `filter`(최대 256자), `edit`(boolean, 기본 true)를 기존 목록/편집기에 전달한다. 실행 전 Tool 입력 검증이 실패하면 실행하지 않은 상태와 실제 입력 명세를 모델에 돌려주어 원래 호출 한도 내에서 수정할 수 있다. 실제 DB/외부 호출의 실패를 자동 재실행하지 않는다.

오류 화면은 `diagnostic.code`, 가능하면 `tool`, `requestId`와 상세 내용을 보존한다. 서버 로그에는 같은 요청 ID와 안전한 오류 코드·Tool 이름만 기록하고 질문·정의 본문·모델 응답·인증 내용을 기록하지 않는다. 기존 문자열 형식의 대화 오류 코드도 표시한다. 다른 기능의 진단 노출 규칙은 유지한다.

2026-11-27 후속 제보의 당시 HTTP 오류는 기존 기록만으로 직접 원인을 특정하지 못했다. 같은 문장의 초기 재시험에서는 HTTP 200이지만 새 용어 등록으로 잘못 연결되는 문제를 확인했다. 수정 후 실제 교육용 모델과 브라우저에서 기존 정의 목록·선택·로컬 수정·적용 없는 변경안까지 확인했다. 별도의 잘못된 문맥 입력을 의도적으로 주입한 시험에서는 HTTP 400의 코드·요청 ID가 화면에 표시되고 서버 로그와 연결되는지 검사했다. 이 주입 오류를 사용자가 겪은 원인으로 간주하지 않는다.

완료 확인: 실제 교육용 모델로 모호한 추천→수락→다른 추천, 원본 복제, 테이블 조회·선택, 모델 설명, ADMIN 안내를 검사한다. 실제 모델 검증과 모의 검증을 구분한다. 이 설계만으로 전체 메뉴의 모든 변경 작업이 지원된다고 표시하지 않는다.

## 2026-11-27 실제 검증

교육용 합성 계정과 OCI 경유 모델로 이름 추천→수락→다른 추천·수락, 테이블 표시·선택, 활성 프로파일/모델 조회, ADMIN 시멘틱 권한 안내를 확인했다. 조회 질문이 테이블 전체 선택을 뜻하지 않는지도 대조했다. Chrome의 실제 채팅에서는 11개 메시지·모델 호출 12회로 생성 시작, 추천, 초안 수정, 테이블 선택, 기존 원본 복제 초안, 모델 설명, 적용 없는 생성안 확인, 클릭 가능한 실행 이력 메뉴 안내까지 확인했다. 데스크톱과 390px 너비를 검사했다.

이번 LLM 대화 시험에서는 신규 DB 객체 생성·권한 변경·생성 SQL 실행을 하지 않았다. 기존 생성·적용·이력 서비스의 앞선 실제 검증과 구분한다. 모든 등록 Tool과 모든 고객 환경이 이번 실제 모델 시험에서 검증된 것은 아니다. 초기 시험에서 드러난 정형 입력 오인, 미수행 안내, 최종 답변의 임의 작업, 줄바꿈 JSON 해석 실패, 추천 참조와 파라미터 문제는 실패 기록을 보존하고 재검증했다. 자동 검사와 실제 모델·화면 검증을 함께 사용하며 모델의 모든 응답을 보장하지 않는다.
