# 목적별 준비 진단

DB Companion에서 처음 설정하는 사용자가 필요한 설정 화면과 확인 순서를 찾도록 돕는 기능입니다. 워크스페이스의 **시작·준비 진단**(`/ai-setup`)에서 시작합니다.

## 사용 순서

1. 테이블 자연어 조회, 업무 정의 연결, 외부 MCP 지식 연결 중 목적을 선택합니다. MCP 항목은 Select AI가 외부 지식을 참조하는 구성입니다. DB 도구를 MCP 서버로 공개하는 설정이 아닙니다.
2. 로그인 계정의 프로필을 선택합니다. 프로필이 없다면 기존 프로필 화면에서 생성한 뒤 돌아옵니다.
3. 설정 확인 결과에서 필요한 항목을 펼칩니다. 설정 화면은 별도 탭으로 열려 진단 화면을 유지합니다.
4. 수정 후 진단 화면에서 **설정 다시 확인**을 누릅니다. 조회 결과를 새로 가져오며 DB 설정을 변경하지 않습니다.
5. Select AI 테스트에서 같은 프로필을 선택해 프롬프트, 생성 SQL, 실제 결과를 확인합니다. 실행 이력에서 실패 정보를 확인할 수 있습니다. 테스트 실행은 별도의 외부 전송·비용 확인 흐름을 따릅니다.

## 확인 범위

| 항목 | 확인하는 내용 | 추가 확인이 필요한 내용 |
|---|---|---|
| 프로필 | ENABLED 상태 | 실제 모델 요청 성공 |
| 제공자·모델 | 속성값 존재 | 모델 가용성, 제공자 기본값, 리전 지원 |
| 조회 대상 | object_list 배열의 owner·name 구조 | 객체 존재, SELECT 권한, 결과 정확성 |
| Credential | 사용 가능한 Credential 목록에 포함됨; Resource Principal 포함 | 외부 인증, OCI IAM 정책 |
| Semantic Source | 앱 검증 버전·API·조회 뷰, 연결된 소스의 활성 상태; MCP 목적은 MCP 소스 포함 여부 | callback 및 도구 실행, 정의·응답의 품질 |
| 외부 접속·실행 결과 | 안내와 기존 설정·테스트 화면 연결 | 실제 호출과 업무 정답 검증 |

메타데이터 조회 실패는 **아직 확인하지 않음**으로 표시합니다. 프로필 조회 자체가 실패하면 설정이 없다는 메시지 대신 조회 실패를 표시합니다. 사용자 소유 스키마에서만 진단하며 조회용 공통 연결과 기존 Repository를 사용합니다. 비밀번호·키·Credential 본문을 읽거나 표시하지 않습니다.

외부 조치는 담당자를 구분합니다. DB ADMIN은 필요한 외부 호스트 권한과 DB 인증을, OCI 관리자는 해당 리전·Compartment의 서비스 사용 권한을 확인합니다. Vault·Identity Domain은 그 서비스를 사용하는 구성에만 해당합니다. 이 화면이 OCI 정책을 조회하거나 생성하는 것은 아닙니다.

## 현재 구현과 후속 범위

**이력·기록 준비**는 다음 항목을 읽기 전용으로 검사합니다. 필요한 이력만 설정하며, 준비 상태를 확인한다고 저장소 설치·감사 활성화·이력 수집을 실행하지 않습니다.

- 문제·복구·용어 변경의 공통 `DBC_APP_RECORD` 저장소 구조
- 선택 프로필의 `conversation` 설정과 대화 이력 뷰 필수 컬럼 조회 가능 여부
- 프로필 변경 이력 보관 구조, 감사 활성화, 기존 수집 준비 판정
- 감사 원본 조회, 보관·설정 테이블, 수집 패키지, 스케줄 활성화, 수집 주기·보존일

대화 설정과 뷰 조회가 준비되어 있어도 실제 호출에는 대화 ID가 필요합니다. A/B 비교는 대화 저장을 사용하지 않습니다. 테이블·컬럼·행 변경 이력은 객체별 설정이므로 전체 준비로 판정하지 않고 대상 화면으로 안내합니다. 조회 권한 부족은 미설치나 비활성으로 단정하지 않습니다. 실제 기록 내용·최근 수집 성공 여부는 각 이력 화면에서 별도로 확인합니다.

현재 구현은 목적 선택, 읽기 전용 설정 진단, 기존 화면 연결, 재진단입니다. 설정 확인과 실제 요청 결과를 별도로 표시합니다. **현재 세션의 확인 결과**에서 선택한 프로필의 최근 SQL 생성·프롬프트 구성·대화 응답과 연결된 SQL 실행 결과를 확인합니다. 결과 ID와 요청 시각을 표시하며, 다른 프로필·소유자의 결과는 제외합니다. SQL 실행은 생성 결과 ID가 일치할 때만 연결합니다.

이 결과는 현재 로그인 세션에 한정됩니다. 설정 변경 전에 얻은 결과일 수 있으며, 정상 응답이나 SQL 실행 성공은 업무 정답을 증명하지 않습니다. 지속 보관할 증거와 조치 내용은 **실패·복구 이력** 링크로 이동하여 문제 질문에 저장합니다.

Select AI 테스트의 **선택 용어 첨부 전후 비교**는 같은 프로필·질문으로 A에는 추가 용어를 첨부하지 않고 B에 선택한 용어 정의·버전·참조 SQL을 첨부합니다. 먼저 업무 용어 참고를 켜고 검색 결과를 선택합니다. 전송 계획 확인 후 A/B SQL 생성은 각각 한 번씩 실행하며, SHOWPROMPT는 별도 요청입니다. 생성된 SQL은 아직 실행 결과가 아닙니다.

이 비교는 **추가 첨부**의 효과를 확인합니다. 프로필에 이미 연결된 Semantic Source와 Feedback는 양쪽에 유지합니다. 기존 지식까지 모두 제거한 대조 실험이라고 해석하면 안 됩니다. 용어 변경·프로필 변경을 호출 전에 검사하고, 전송에 사용한 용어 스냅샷은 결과와 함께 보관합니다. 기대 정답은 생성 요청에 넣지 않고 문제 질문의 별도 검토 기준으로 둡니다. 비교 결과는 기존 버튼으로 문제 질문에 명시적으로 저장할 수 있습니다.

문제 질문의 **실패·복구 이력**에서 조치 전 기록, 선택적인 재시험 기록, 확인한 원인, 수행한 조치, 확인 결과·남은 문제를 저장합니다. 연결 대상은 같은 문제 질문의 기록으로 제한합니다. 조치 메모는 `MANUAL_RECOVERY` / `USER_REPORTED_NOT_VERIFIED`로 보관하며, 재시험을 실행하거나 자동으로 성공 판정하지 않습니다. 기존 `DBC_APP_RECORD` 저장소를 사용하며 새 스키마 객체를 만들지 않습니다. 저장이 불확실하면 자동 재시도하지 않고 목록에서 확인합니다.

**보관된 프로필 기록**에서 로그인 세션이 끝난 뒤에도 남아 있는 DB 대화 기록과 저장된 테스트 기록을 확인합니다. 선택 프로필 이름이 정확히 일치하는 기록만 각각 최근 10건까지 표시합니다. ID·기록 시각·유형을 펼쳐 보고 기존 이력 화면으로 이동할 수 있습니다. 대화 기록은 생성 시각, 테스트 기록은 저장 시각 순서입니다. 기존 대화 이력 화면의 조회 기간은 별도로 조정할 수 있습니다.

조회 성공 후 기록이 없는 경우와 조회 실패를 구분합니다. 보관 기간이 지났거나 기록 설정이 꺼져 있었다면 실행했어도 기록이 없을 수 있습니다. 수동 입력한 테스트 기록도 포함될 수 있으며 복구 메모는 제외합니다. 과거 기록이나 저장 성공을 현재 실행 성공·업무 정답으로 판정하지 않습니다. 질문·응답 원문은 이 진단에서 조회하지 않고, 보관 기록은 AI 분석 입력에 추가하지 않습니다. 저장소 생성·수집·모델 호출은 수행하지 않습니다.

후속 범위는 저장된 결과의 내용·설정 버전을 대조한 진단, Native Semantic Source의 완전한 적용/미적용 비교입니다. 자연어 설정은 아래 AI 설정 도우미에서 대화 기록 활성화부터 지원하며, 다른 설정 작업은 후속 범위입니다.

## AI 설정 도우미 사용 및 호출 구조

AI 모드는 기존 AI Assistant에서 선택한 모델을 사용합니다. 자연어 생성·편집 전용으로 별도 DB 수정 경로를 만들지 않고 화면이 사용하는 서비스 인터페이스를 호출합니다. 입력 검증·소유자 제한·미리보기·적용 확인·읽어서 검증·오류 기록은 화면과 AI 호출에 동일하게 적용합니다. 모델 출력이 직접 SQL 실행 권한이나 변경 승인을 대신하지 않습니다.

기능별 기준은 `src/main/resources/setup/capabilities.json`에서 버전 관리합니다. 목적별 필수 조건, 조회 기능, 담당자, 설정 화면, 지원하는 변경과 검증 절차를 정의합니다. 화면과 AI 요청 모두 이 명세를 사용하며, 진단값이 없는 조건은 준비 완료가 아닌 미확인으로 처리합니다. 명세의 함수 이름은 문서상 매핑이며 임의 코드 실행 지시가 아닙니다.

**AI 설정 도우미**는 AI 도우미 설정에서 선택한 모델에 공통 명세와 현재 진단을 전달합니다. 하려는 일을 입력하고 전송 내용을 확인한 뒤 분석을 요청합니다. Credential 본문·대화 원문·업무 행 데이터는 진단 입력에 포함하지 않습니다. 입력한 질문은 전송되므로 비밀값을 입력하지 마세요.

첫 적용 작업은 선택 프로필의 `conversation=true`입니다. AI가 제안하면 변경안 보기에서 현재 값·대상 프로필을 확인하고 별도로 적용합니다. 명세의 선행 조건을 다시 확인하며 기존 `ProfileEditService`의 변경 전후 이력·버전 확인·읽어서 검증을 재사용합니다. 실패나 불확실한 응답은 자동 재시도하지 않습니다. 적용 후 설정 다시 확인으로 재진단합니다. 이력 저장소 생성·감사 활성화·권한·OCI 설정 등은 기존 설정 화면에서 처리합니다. 임의 SQL 실행이나 모든 설정의 자연어 편집을 지원하는 것은 아닙니다.

재사용 경계는 진단의 `AiSetupService`·`AiSetupHistoryService`, AI 모델·일회성 동의 상태의 기존 `AiAssistant`, 프로필 변경의 `ProfileEditService`, 비교의 `SelectAiTestService.glossaryComparisonPreview`, 복구 기록의 `ProblemQuestionService.saveRecovery`입니다. SQL 생성·비교·이력 생성 전체를 자연어로 조합하는 기능은 후속 범위입니다.

사용성 효과는 아직 측정하지 않았습니다. 같은 난도의 과제를 Companion 사용·미사용으로 나눠 순서를 교차 배치하고, 완료 시간(대기 시간 별도), 실패 원인, 도움 요청 횟수, 스스로 복구했는지, 설정 이유를 설명할 수 있는지 비교합니다. SQL이 실행됐다는 사실만으로 업무상 성공으로 계산하지 않습니다.

## 검증 기준

- 설정 누락과 조회 권한 오류를 구분합니다.
- 다른 스키마 선택 및 로그인 만료 시 DB 조회를 진행하지 않습니다.
- 네 언어에서 화면이 렌더링되고 프로필 이름은 HTML·URL 경계에 맞게 처리됩니다.
- 메뉴는 인증이 필요하며 언어 전환이 로그인 화면으로 잘못 이동하지 않습니다.
- 실환경 검증에서는 목적 선택 → 프로필 선택 → 진단 → 설정 링크 → 재진단을 확인합니다. 모델 호출·DB 변경은 이 읽기 전용 검증에 포함하지 않습니다.
