# 프로파일 생성 대화와 ADMIN 권한 질문

사용자가 프로파일이 없는 상태에서도 생성 요청을 시작하고 테이블·모델·인증 참조를 선택해 기존 생성 서비스로 적용한다. 권한 질문은 대상 프로파일 선택 없이 ADMIN 조치 안내를 조회한다.

2026-11-27 구현 범위: C01~C05의 생성 초안·단계별 입력·수정·취소·생성 재조회/이력, C07의 기능별 ADMIN 안내, O11 화면 안내, O02의 대표 질문 확인. 기존 `AiCreationService`, `ProfileEditRepository`와 Select AI의 선택·미리보기·생성·실행 서비스를 재사용한다. 별도 MCP·설정 저장소·임의 SQL 실행기를 추가하지 않는다. 첫 연결은 대화 명령/선택기이며 AI의 자유 문장 생성 계획 전체 지원과 구분한다.

초안은 현재 문서 메모리에만 둔다. 생성 이름·설명·상태·provider/model·credential 이름·region/compartment·object_list를 유지한다. 소유자 범위로 신규 조회 API를 제공하며 현재 계정에서 보이는 객체와 기존 동일 제공자 프로필의 모델 후보만 조회한다. 후보는 지원/접속 성공 보장이 아니다. 모델 비밀값을 받지 않는다.

테이블 목록은 서버의 조회 결과 ID에 연결한다. 목록 번호와 이름이 불명확하면 재질문하고, 추가/제외/교체를 구분한다. 최종 생성은 기존 preview/create API의 입력·토큰·확인/전송 동의를 사용한다. 수정·취소·새 요청은 현재 변경안을 무효화한다. 생성 결과 검증이 불확실하면 자동 재시도하지 않는다. 생성 확인과 대표 질문 실행은 별도다.

ADMIN 안내는 읽기 전용이며 실행하지 않는다. 기존 안내의 권한 SQL·목적·실행자·완료 확인·관련 준비 화면을 반환한다. 일반 사용자는 자기 계정 대상, ADMIN은 입력한 일반 사용자 대상 안내를 볼 수 있다. 대상 식별자를 검증하며 계정 존재/현재 권한은 확인하지 않았다고 명시한다. 패키지 소유자·객체별 위임·네트워크 호스트처럼 실제 환경 확인이 필요한 항목은 기존 사전 확인 화면으로 연결하며 광범위한 권한을 임의 생성하지 않는다.

검증: 입력 분류·누적 선택·모호한 참조·취소/미동의·이름 충돌·API 오류의 자동 검사, 소유자 범위/필터·ADMIN 안내 대상 검증, PC/모바일 브라우저의 전체 입력/미리보기. 실제 DB 생성은 별도 승인된 교육 계정에서 생성값·이력과 비교한다. 앱 기존 실행 포트에는 자동 배포하지 않는다.

## 같은 대화에서 질문 확인

생성 결과의 **질문으로 확인** 또는 “질문으로 확인” 명령으로 시작한다. 대상 프로필의 모델을 사용하며 도우미 분석 모델을 추가로 선택하지 않는다. 질문과 전송 정보를 검토하고 호출 1회 비용에 동의한 뒤 SQL을 생성한다. 생성 SQL은 별도 검토·실행 확인을 거친다. Select AI 실행 서비스가 허용하는 조회만 수행하며 앱의 기존 토큰·소유자·SQL 검사·시간 제한을 유지한다. 확인 중 새 질문·취소는 화면의 이전 실행 확인을 무효화한다.

결과 표는 기존 자연어 조회 화면의 표시기를 공통 모듈로 추출해 재사용한다. 행 페이지, NULL, 셀/행 잘림, 실행 주체·시각을 동일하게 표시한다. AI 응답 실패·SQL 검토 실패·실행 오류는 성공으로 답하지 않으며 자동 재시도하지 않는다.

## 실제 시험에서 발견한 생성 오류

교육용 계정의 빈 설명 생성 요청은 JDBC 바인딩 단계에서 `0 char of CLOB data cannot be read`로 실패했다. 두 번의 실제 생성 API 시도는202·미확인으로 중단했고 변경 이력을 남겼다. 각 시도 뒤 동일 이름의 객체가 없음을 확인한 다음 새 변경안으로 진행했다. 별도 JDBC의 NULL 블록 시험으로 길이0 Reader CLOB 바인딩 오류를 재현했으며 CREATE_PROFILE을 실행하기 전의 실패임을 확인했다.

`AiCreationRepository`에서 빈 설명을 SQL NULL로 바인딩하도록 수정했다. 비어 있지 않은 설명은 기존 CLOB Reader를 유지한다. 바인딩 회귀 검사와 전체 Java1,589건·PMD가 통과했고, 수정 후 실제 대화 UI에서 생성200·재조회 일치·생성 이력과 PC/모바일 화면을 확인했다. 이전 두 실패 기록은 보존했다. 이 수정은 공통 생성 경로의 빈 설명 처리이며 모든 Agent/Task/Tool 생성의 실제 실행 검증을 뜻하지 않는다.

일반/ADMIN의 10개 기능 안내와 타 계정·잘못된 입력 거절을 실제 HTTP25건으로 확인했다. ADMIN 브라우저에서 대상 일반 계정을 묻는 흐름과 실행 내역 바로 안내를 확인했다. 권한 부여0회·모델 호출0회다. 별도 대표 질문 시험과 후속 동일 대화창 시험에서 생성한 프로필로 ACTIVITY의 날짜별 전체 행 수를 집계했고 모두 APAC4·EU5·US2로 독립 SELECT와 일치했다. 모델은 OCI 경유 openai.gpt-5.4-mini, SQL 생성은 각 시험1회로 총2회였다. 생성 SQL을 확인한 후 실행했고 대화창의 결과 표·PC/390px 화면·AI와 SQL의 별도 동의·브라우저 스크립트 오류0건을 확인했다.

최종 자동 검사: Java1,589건·JavaScript756건 통과, 의도적skip1건·PMD0. 공개 파일 검사와 공백 검사도 통과했다. 합성 계정의 특정 제공자·모델·테이블에 대한 결과이며 다른 제공자 인증, 여러 의도를 담은 자유 문장 계획, 신규 Source/Callback 구성, 다중 계정의 영속 작업 재개까지 검증한 것은 아니다.
