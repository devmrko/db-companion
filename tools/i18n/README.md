# 화면 문구 관리

한국어(기본), 영어, 중국어 간체, 일본어를 지원한다. `messages*.properties`는 UTF-8이다.
DB 코멘트·Annotation·질문·SQL·설정값·Oracle 오류 원문은 번역하지 않는다.

## 수정 방법

- `catalog.json`은 최초 분리한 문구의 키·한국어·출처 목록이다. 배열 순번은 번역 파일의
  식별자이므로 기존 항목을 재정렬하지 않는다. `01-`~`09-` JSON의 값 순서는 영어/간체/일본어다.
- 기존 문구를 수정할 때 해당 번역과 한국어 원문을 함께 수정하고 다음 명령을 실행한다.
  `node scripts/i18n-bundles.cjs`
- 생성 결과는 `src/main/resources/i18n/messages*.properties`에 저장된다. 실행 중 외부 번역
  서비스는 호출하지 않는다. 초기 문구 키는 중복 제거를 위한 해시이며 출처는 catalog에서 찾는다.
- 새 기능은 의미 있는 메시지 키를 사용한다. 공통 키는 생성 스크립트의 common 목록에서 관리한다.
- 기능별 문구는 `feature-*.json`에 한국어/영어/간체/일본어 순서로 관리한다.
  함수 화면과 기존 행 이력 문구도 이 파일에서 재생성해 누락을 방지한다.
- OCI 모델 선택 및 임베딩 입력 용도 도움말은 `vector-oci.json`에서 한국어/영어/간체/일본어 순서로 관리하며
  같은 생성 명령을 사용한다.
- 번역의 `{0}` 같은 인자는 삭제하지 않는다. JS/Java는 인자를 한 번만 대입하며 원문 값을
  번역하거나 HTML로 해석하지 않는다. `{query}`는 실제 Task 설정의 토큰이므로 그대로 둔다.

## 적용 위치

- Thymeleaf: `#{키}`, 조건식 내부는 `#messages.msg('키')`.
- JS: `t('키', '한국어 기본 문구', ...인자)`. 같은 Spring 번들을 `/i18n/messages.js`로 받는다.
- Java: `UiMessages.text('키', '기본 문구')`에 해당하는 Java 문자열 표기를 사용한다.
- 세션 캐시의 상태/권한 안내는 `UiNotice`로 보관해 표시 시점에 언어를 정한다.
  객체 이름·권한·DB 오류는 raw 노드로 유지한다. 언어 전환 때문에 DB를 재조회하지 않는다.
- 영속 저장하는 진단 상태/시험 입력은 원문으로 유지한다. 이력 기록을 소급 번역하지 않는다.

## 검증

`node --test src/test/js/*.test.mjs`는 번역 누락과 인자 일치를 검사한다.
`mvn -Pquality verify`는 실제 HTTP/Thymeleaf와 기존 회귀 및 PMD를 검사한다.
공개본 검증 범위는 `docs/validation.md`에 기록한다. 고객 환경 진단 보고서는 공개본에 포함하지 않는다.
