앱에서 저장한 등록·수정의 변경 전후 내용과 변경자·시각을 보관합니다. 과거 변경이나 직접 SQL 변경은 소급 수집하지 않습니다. 이력 저장 실패 시 용어 저장도 취소됩니다.

이력 조회: 아래 '등록 용어'에서 각 용어의 '변경 이력'을 누르세요.

SQL / PLSQL로 관리하려면?

생성 버튼은 실행 전에 실제 DDL을 보여줍니다. 아래는 조회·등록·수정의 대응 SQL입니다. 자리표시자와 바인드 값을 실제 환경에 맞게 지정하세요. SQL 기준은 실행하지 않는 설명 데이터입니다.

-- 로그인 소유 스키마에서 조회 (SELECT 권한)
SELECT TERM_ID, REVISION, TERM_TEXT, ALIASES_JSON,
       DEFINITION_TEXT, SQL_CRITERIA, ENABLED_YN
FROM DBC_BUSINESS_TERM ORDER BY TERM_TEXT;
-- 등록 (INSERT 권한): :search_text는 대표 용어+별칭+정의입니다.
INSERT INTO DBC_BUSINESS_TERM
  (TERM_ID,REVISION,TERM_TEXT,ALIASES_JSON,DEFINITION_TEXT,
   SQL_CRITERIA,ENABLED_YN,SEARCH_TEXT)
VALUES (:uuid,1,:term,:aliases_json,:definition,
        COALESCE(TO_CLOB(:criteria),EMPTY_CLOB()),'Y',:search_text);
-- 수정 (UPDATE 권한): 이전 버전이 일치할 때만 변경, 변경 행 수 확인
UPDATE DBC_BUSINESS_TERM
SET TERM_TEXT=:term, ALIASES_JSON=:aliases_json,
    DEFINITION_TEXT=:definition, SQL_CRITERIA=COALESCE(TO_CLOB(:criteria),EMPTY_CLOB()),
    SEARCH_TEXT=:search_text, ENABLED_YN=:enabled,
    REVISION=REVISION+1, UPDATED_AT=SYSTIMESTAMP
WHERE TERM_ID=:uuid AND REVISION=:expected_revision;
-- 확인 후 COMMIT; 사전 Text 인덱스는 SYNC (ON COMMIT).
-- 위 직접 SQL은 앱 변경 이력에 자동 기록되지 않습니다.
-- 앱 이력: 신규/수정 값과 전후 JSON을 같은 트랜잭션으로 저장합니다.
SELECT ACTOR, RECORDED_AT, PAYLOAD
FROM DBC_APP_RECORD
WHERE RECORD_TYPE='BUSINESS_TERM_HISTORY'
  AND JSON_VALUE(PAYLOAD,'$.termId')=:uuid
ORDER BY SEQ DESC;
-- 형태소 추출: 설정된 정책을 사용하며 AI 호출은 없습니다.
DECLARE tokens CTX_DOC.TOKEN_TAB;
BEGIN
  CTX_DOC.POLICY_TOKENS('DBC_BT_KO_POLICY',:question,tokens,format=>'TEXT');
  FOR i IN 1..tokens.COUNT LOOP
    DBMS_OUTPUT.PUT_LINE(tokens(i).token);
  END LOOP;
END;
